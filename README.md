# Weather Summary

A tiny, open-source weather app + Home Assistant integration that answers one question, as a **short sentence**:

> "Rain starting in ~20 min." · "Light rain easing, should stop in 10 min." · "Sunny 28°, drizzle after 3 pm."

The sentence is generated by a **free AI** from raw forecast data and shown on:
- the Android app screen,
- a **home-screen widget** (small text, easy to read),
- **Home Assistant** sensors (via the included custom integration).

## Why it is structured this way

```
┌────────────────────────────┐        ┌──────────────────────────────┐
│  android/  (Kotlin +      │        │  ha/custom_components/       │
│   Jetpack Compose app,     │        │   weather_summary/           │
│   real home-screen widget) │        │   (HACS-style integration)   │
└────────────────────────────┘        └──────────────────────────────┘
        │                                        │
        │  1. Weather source (pluggable)         │  same choice
        ▼                                        ▼
  Open-Meteo · OpenWeatherMap · WeatherAPI.com
        │
        │  2. Normalize → WeatherSnapshot (one data model, works everywhere)
        ▼
  Derive useful facts (rain_start_in_min, rain_stop_in_min, precip_next_hour, …)
        │
        │  3. AI "recipe" = compact prompt (shared, see docs/RECIPE.md)
        ▼
  Gemini (free tier) · Ollama · Home Assistant (its own LLM / you configure once)
        │
        ▼
  ONE short sentence  →  widget + app screen + HA sensor
```

Everything is **provider-agnostic** so it can be extended to more weather APIs
(Tomorrow.io, AccuWeather…), more AI backends, or more platforms (the same
`WeatherSnapshot` + prompt recipe can be ported to iOS/Flutter/ESPHome later).

## Quick start (Android)

1. Open `android/` in **Android Studio** (Hedgehog or newer).
2. Run on a device/emulator. It works out of the box with **Open-Meteo** (no API key) + **Gemini** free tier.
3. For Gemini: get a free API key at <https://aistudio.google.com/apikey> and enter it in **Settings**.
   - No key yet? The app shows a smart *fallback sentence* built from the raw facts instead.
   - Prefer local AI? Enable **Ollama** (point it at your Home Assistant add-on) — no key, fully private.
   - Already using HA? Pick **Home Assistant** as the AI provider and configure the LLM once in HA.
4. Add the **"Weather Summary" widget** to your home screen. It refreshes in the background.

## Quick start (Home Assistant)

The integration lives in `ha/custom_components/weather_summary`. Install it by
copying that folder into `<config>/custom_components/`, or (for HACS) push the
`ha/` folder to its own repo like `weather-summary-ha`. See `ha/README.md`.

1. Restart HA, add the **Weather Summary** integration, pick weather provider + LLM.
2. Entities `sensor.weather_summary_text`, `sensor.weather_summary_temperature`, … appear.
3. You can also **push from the phone**: the app can send its latest forecast + sentence to HA
   (`services: weather_summary.ingest_app`) and read AI text back
   (`POST /api/weather_summary/generate`), so HA stays fresh even when the phone is the one polling.

## FAQ

**Do I need to log in / pay for the AI?** No. It runs out of the box with a
built-in template sentence. For the smarter sentences, add a **free Gemini API
key** (aistudio.google.com/apikey), use a local **Ollama** (no key), or point at
your **Home Assistant** LLM. Free-tier Gemini ≈ 1,500 requests/day — a widget
refreshing every 15 min uses ~96/day, so there's no practical limit.

**Why Open-Meteo and not Windy?** Windy's *free* API is test-only (500/day,
"randomly shuffled data") and excludes ECMWF; the accurate windy.com data needs
the paid Professional tier. Open-Meteo blends ECMWF/ICON/GFS and adds 15-minute
radar nowcasting — the thing that powers "rain in ~20 min". See `docs/RECIPE.md`
§6 for how to add a Windy pro-key provider later (it's a one-interface change).
