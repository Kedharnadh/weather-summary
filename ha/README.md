# Weather Summary for Home Assistant

Custom integration that turns raw forecast data into a **short, readable weather
sentence** ("Rain starting in ~20 min."), generated by a free LLM, and exposes it
as sensors. Comes with a matching [Android app](../android) — the phone can push
its own fresh forecast + sentence into HA so the sensors stay current even when
the phone is the one polling.

Not affiliated with any weather provider. Data from **Open-Meteo** (no key),
**OpenWeatherMap** or **WeatherAPI.com** (free keys), depending on what you
configure.

## Entities

| Entity | Details |
| --- | --- |
| `sensor.weather_summary_text` | The AI sentence (short, widget-ready). |
| `sensor.weather_summary_temperature` | Current temperature (°C). |
| `sensor.weather_summary_apparent_temperature` | Feels-like (°C). |
| `sensor.weather_summary_humidity` | Relative humidity (%). |
| `sensor.weather_summary_wind` | Wind speed (km/h). |
| `sensor.weather_summary_condition` | WMO condition label. |
| `binary_sensor.weather_summary_is_raining` | True when precip ≥ 0.2 mm. |
| `sensor.weather_summary_rain_starts_in` / `rain_stops_in` | Minutes (diagnostic). |
| `sensor.weather_summary_precipitation_next_hour` | mm (diagnostic). |
| `sensor.weather_summary_rain_chance_next_24_h` | % (diagnostic). |
| `sensor.weather_summary_peak_temperature_next_24_h` | °C (diagnostic). |
| `sensor.weather_summary_updated` | Timestamp of last refresh. |

## Installation

HACS expects `custom_components` at the **repository root**, so this monorepo
(`android/` + `ha/`) is not HACS-installable as-is. Pick either:

1. **Manual (quickest)** — copy the folder into your config:
   ```
   config/
     custom_components/
       weather_summary/   ← from ha/custom_components/weather_summary
   ```
   then restart Home Assistant and add **Weather Summary** via Settings →
   Devices & Services.

2. **HACS** — push the `ha/` folder to its own GitHub repository (like
   `weather-summary-ha`, mirroring the companion app repo), then add it as a
   custom repository with category **Integration**. The included GitHub
   workflows stage the `ha/` contents at the repo root before running HACS
   validation / hassfest, so a repo root == `ha/` layout validates cleanly.

Setup steps in both cases:
1. Settings → **Devices & Services** → Add integration → **Weather Summary**.
2. Fill the form:
   - **Lat/Lon** — defaults to your HA home coordinates;
   - **Weather provider** — Open-Meteo (no key) / OpenWeatherMap / WeatherAPI.com;
   - **LLM provider** — `openai_compatible` (Ollama: `http://<host>:11434/v1`,
     model `llama3.2`; keys optional) · `homeassistant` (uses the LLM configured
     in HA) · `none` (built-in template, no AI);
   - **Scan interval** in minutes.

There is no YAML setup — this integration is config-flow only.

## Using it from the Android app

The app is provider-agnostic. You can either:

1. **Use HA as the AI backend** — in the app settings choose *AI provider →
   Home Assistant*, enter your HA URL + long-lived token (Profile → Security).
   The app then calls `POST /api/weather_summary/generate` and shows whatever
   sentence your HA-configured LLM produces.
2. **Push from the phone** — enable *Push to HA* in the app. It calls the
   `weather_summary.ingest_app` service with its latest forecast + sentence, and
   HA sensors update without polling.

Both work over the normal REST API; a Bearer token is required.

## Services

| Service | Description |
| --- | --- |
| `weather_summary.generate` | Generate a sentence from a `prompt` (optional `tiny: true` for ≤ 60 chars). Returns `{"text": ...}`. |
| `weather_summary.ingest_app` | Accepts a `payload` dict (temperature, summary, weather_code, is_raining, rain_start_in_min, …) pushed by the app and reflects it into the sensors. |
